# WEKA Local WEKA Home (LWH) Setup

Use this script to install **Local WEKA Home** on a client VM for demos and testing.  
Local WEKA Home is the self-hosted version of the WEKA monitoring and management platform — the same UI and analytics as cloud WEKA Home, running entirely on a VM you control.

---

## Prerequisites

| Requirement | Notes |
|-------------|-------|
| Linux host (amd64) | A WEKA client node works well; boot disk ≥ 20 GB |
| Root / sudo access | Required throughout |
| Internet access | To download the bundle from get.weka.io |
| `curl` + `openssl` | Usually pre-installed on most distros |
| `python3` **or** `jq` | Used to parse the version list |
| get.weka.io token | Your customer download token |

---

## Token setup

The script looks for a `.env` file in the `wekahome/` directory:

```bash
# wekahome/.env
WEKA_TOKEN=your_token_here
```

If the file is not found, you are prompted for the token the first time you run the script. You can choose to save it to `.env` so you don't have to type it again. The file is created with `chmod 600` so only root can read it.

> `.env` is in `.gitignore` and will never be committed to the repo.

## Usage

```bash
chmod +x wekahomesetup.sh
sudo ./wekahomesetup.sh
```

## What the script does

### 1 — Detect local IP
The script finds the node's first non-loopback IPv4 address.  This IP is used for the TLS certificate and printed at the end as the URL for `weka cloud enable`.

### 2 — Load (or prompt for) your token
Reads `WEKA_TOKEN` from `.env` in the script directory. If not found, you are prompted and given the option to save it for future runs.

### 3 — Fetch available versions
Queries the get.weka.io releases API using your token and displays a table of the 10 most recent LWH releases:

```
  Available WEKA Home versions:

  #    Version     Released      Highlights
  ---  -------     --------      ----------
  [1]  4.4.4       2026-05-06    Even better things...
  [2]  4.4.2       2026-03-17    Better things...
  [3]  4.4.1       2026-03-08    Good things....
  ...
```

Press Enter to accept the latest, enter a number to pick a specific version, or type a custom version string.

### 4 — Generate a self-signed TLS certificate
Creates a 2048-bit RSA certificate valid for 365 days, with a Subject Alternative Name (SAN) set to the node's IP address.  This is what lets WEKA backend nodes connect over HTTPS without a CA-signed cert.

### 5 — Download the bundle
Downloads `wekahome-<version>.bundle` from get.weka.io using your token.  The bundle is a self-contained installer — no package manager required.

### 6 — Run the installer
Runs `bash wekahome-<version>.bundle`, which installs K3s and deploys LWH into the `home-weka-io` namespace.  This step takes a few minutes and produces its own progress output.

### 7 — Configure homecli
Runs `homecli local setup` with the generated TLS certificate and private key to wire up the local LWH instance.  The cert files are deleted after this step.

### 8 — Print credentials and next steps
Retrieves the auto-generated admin and Grafana passwords from Kubernetes secrets and prints everything you need:

```
------------------------------------------------------------------
  WEKA Home credentials
------------------------------------------------------------------
  Admin password:        <auto-generated>
  Grafana password:      <auto-generated>
------------------------------------------------------------------

  Enable local WEKA Home (run on a WEKA client node):

  weka cloud enable --cloud-url http://<LOCAL_IP>
  # or with TLS:
  weka cloud enable --cloud-url https://<LOCAL_IP>
------------------------------------------------------------------
```

Note that https needs either a signed certificate or a debug override, so use use http for demo purposes.

## After installation

Make sure your WEKA client is authenticated:
```bash
weka status
```
If necesssary, login:
```bash
weka user login admin
```

Run the following on a WEKA client node to point the cluster at your LWH instance:

```bash
weka cloud enable --cloud-url http://<LOCAL_IP>
```
Validate traffic is flowing from backends to local WEKA home:
```bash
weka cloud status
```
Example of good connection is:
```bash
[root@ip-10-0-66-120 wekahome]# weka cloud status

                 url: http://10.0.66.120
        registration: registered
              status: healthy
        stats upload: enabled

HOST        IS HEALTHY
HostId<0>   READY
HostId<1>   READY
HostId<2>   READY
HostId<3>   READY
HostId<4>   READY
HostId<5>   READY
```

Then open `http://<LOCAL_IP>` in a browser.  Log in with username `admin` and the password printed by the script.

> If the VM is in a cloud environment, make sure port 80 and/or 443 is open in the security group / firewall so your browser (and WEKA backend nodes) can reach it.

If using https connection (rather then http) you may get this error when using **weka cloud enable**:
```
[root@ip-10-0-66-120 wekahome]# weka cloud enable --cloud-url https://10.0.66.120
error: Failed registering the cluster in the cloud: curl: (60) SSL certificate problem: self-signed certificate
```
This error is caused by the LWH using a self-signed certificate.   You need to either install a signed cert or set a debug override to use insecure WEKA cloud HTTPS call.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| `Download failed` | Check your token in `.env` and that the host has internet access |
| `homecli: command not found` | The bundle installer failed — check the output of step 6 for errors |
| Browser shows cert warning | Expected with a self-signed cert — click through, or use `http://` instead of `https://` |
| Credentials show `<run kubectl...>` | Run `kubectl get secret -n home-weka-io wekahome-admin-credentials -o jsonpath='{.data.adminPassword}' \| base64 -d` manually |
| WEKA not reporting to LWH | Check firewall — WEKA backend nodes need port 80/443 open to the LWH host |
| https connection self-signed certificate error | Set a debug to allow this or use http |
